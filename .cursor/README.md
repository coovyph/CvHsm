This directory contains the rules, commands, templates, and artifacts that drive the full development lifecycle.

```
│   ├── testing.md         # Testing workflow (spec-driven, coverage thresholds)

│   ├── plan.md            # /plan  — Plan a feature (test cases + ADRs + plan file)
│   ├── develop.md         # /develop — Implement a feature (task-by-task, commit each)
│   ├── test.md            # /test   — Write and run tests (convert spec to code)
│   ├── audit.md           # /audit  — Security audit (OWASP, secrets, dependencies)
```


## Git Workflow (mandatory)

**Every project is git-initialized. Every change goes on a feature branch. Never merge without approval.**

| Rule | Description |
|------|-------------|
| **Auto-init** | `git init` + initial commit if the project isn't a repo yet |
| **Always branch** | Create a branch before any change: `feat/`, `fix/`, `bugfix/`, `chore/`, `doc/` |
| **Never on main** | No commits, no fixes, no refactors directly on `main` |
| **Ask before merge** | Only merge into `main` when the user explicitly tells you to |
| **Pull before push** | Rebase onto latest `main` before pushing the feature branch |

See [Git Rules](rules/git.md) for the complete workflow.

## How to Use

### Start a new feature
```
/plan Add user registration with email verification
```
This produces: test cases, ADRs (if needed), and a plan file. Automatically runs `git init` if the project isn't a repo yet.

### Implement the feature
```
/develop
```
This creates a `feat/user-registration` branch, reads the test cases and plan, implements task-by-task, commits after each. **Does not merge** — waits for your approval.

### Write tests for the feature
```
/test
```
This creates a `test/user-registration` branch, converts the test case specification into actual test code, and reports coverage.

### Audit for vulnerabilities
```
/audit
```
This scans dependencies, checks OWASP compliance, reviews auth, and produces a report. Fixes go on a `fix/` or `bugfix/` branch — never on main.

### Fix a bug
```
/fix The login page crashes when email has a + sign
```
This creates a `fix/login-email-plus` branch, reproduces, diagnoses, adds a regression test, fixes, and verifies. **Does not merge** without your approval.

## Key Principles

1. **Git first** — Every project is a repo; every change is on a branch
2. **Test cases before code** — Write the specification before implementing
3. **Never assume** — Ask the user, don't guess
4. **Branch per change** — `feat/`, `fix/`, `bugfix/`, `chore/`, `doc/`
5. **Never auto-merge** — Only merge into `main` when the user explicitly asks
6. **One commit per task** — Small, focused, verifiable commits
7. **Security is non-negotiable** — Never ship insecure code
8. **Read before writing** — Understand existing patterns first
9. **ADR for decisions** — Document architectural choices for future reference
